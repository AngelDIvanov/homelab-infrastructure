Full cluster + repo audit. Cluster was healthy at audit time; the issues are
startup-ordering fragility ("broken on release") and repo structure/drift.

## "Broken on release" = startup races (self-healing, worth hardening)

| # | Symptom after `k3s-start` | Root cause | Fix |
|---|---|---|---|
| 1 | `pylab` ErrImagePull → CrashLoopBackOff | pulls `registry:30500/pylab:latest` before registry pod is up | add initContainer that waits for registry, or pre-pull/cache |
| 2 | `loki-canary` FailedCreatePodSandBox | flannel `subnet.env` race on node boot | known k3s transient; tolerable |
| 3 | pylab HPA `FailedGetResourceMetric` | metrics-server not ready yet | tolerable; HPA recovers |
| 4 | prometheus-operator `FailedMount admission` | webhook secret mount race on old replica | tolerable |
| 5 | **alertmanager-webhook crashloops on boot** | container command `apk add --no-cache openssh-client && python3 webhook.py` hits the Alpine mirror on every start; `&&` fails if network/mirror not ready | **bake openssh-client into a custom image** (see `Dockerfile.ngrok` pattern) instead of installing at runtime |

Top priority: **#5** — it is the recurring "webhook receiver down" (see
`docs/runbooks/monitoring/webhook-down.md`). Proper fix is a prebuilt image so
the webhook has zero runtime package dependency.
