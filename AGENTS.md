# AGENTS.md — homelab-infrastructure

Instructions for AI coding assistants working in this repo.

## What this is

A self-hosted DevOps lab on **KVM/libvirt**, fully defined as code: VM provisioning,
a kubeadm Kubernetes cluster, monitoring, CI/CD, alerting, and a Claude-driven
auto-healing loop. `README.md` has the full feature tour and screenshots — read it
for context before touching infra.

## Layout

| Path | Purpose |
|---|---|
| `terraform-kubeadm/` | Terraform + libvirt provisioning of the kubeadm nodes. Holds live `terraform.tfstate` — never edit by hand. |
| `terraform/` | The infra VM (NFS server + GitLab CE) outside the cluster. |
| `ansible/` | Config management. `ansible.cfg`, `inventory/` (`kubeadm.ini` is generated by terraform), `playbooks/`, `roles/`. |
| `kubernetes/` | Manifests: deployments, monitoring jobs, backup, policies, self-healing. |
| `monitoring/` | kube-prometheus-stack / Loki / promtail values, alert rules, Grafana dashboards. |
| `scripts/` | `webhook.py` (alert → Claude → Slack bridge) + bash ops scripts. |
| `tests/` | Pytest suite for the security-critical webhook paths (`parse_commands`, `verify_slack`). Run with `python -m pytest tests`. |
| `docs/` | Runbooks, postmortems, audits, images. |
| `.gitlab/` | Self-hosted GitLab CI pipeline definitions. |

## Stack

Terraform (libvirt provider) · Ansible · kubeadm Kubernetes (containerd, Calico,
etcd snapshots every 12h) · MetalLB + Traefik · GitLab CE (self-hosted) ·
Prometheus + Grafana + Loki (31d) + Alertmanager · Vaultwarden (secrets) ·
local Docker registry (NFS-backed).

## Running things

```bash
cd ansible
ansible-playbook -i inventory/kubeadm.ini playbooks/kubeadm-bootstrap.yml   # cluster
ansible-playbook -i inventory/kubeadm.ini playbooks/kubeadm-addons.yml      # MetalLB, Traefik, NFS, registry
ansible-playbook -i inventory/kubeadm.ini playbooks/kubeadm-workloads.yml   # monitoring + apps
../scripts/deploy.sh                      # build + push trengo-search, roll the deployment
../scripts/sync-dashboards.sh             # Grafana dashboards → ConfigMaps
python3 ../scripts/sync-webhook-configmap.py   # after editing scripts/webhook.py
```

## Gotchas

- **Never hand-edit `terraform-kubeadm/terraform.tfstate`** or the `.terraform/`
  dir. Use `terraform` commands.
- **Secrets live in Vaultwarden**, not in the repo. Preserve image SHA pinning
  wherever it exists and keep NetworkPolicy default-deny when adding workloads.
- **The cluster uses etcd**; `kubernetes/backup/etcd-snapshot-cronjob.yaml`
  takes real etcd snapshots. Respect the backup CronJobs in `kubernetes/backup/`.
- **The webhook ConfigMap is generated** from `scripts/webhook.py`; CI fails if
  `kubernetes/deployments/alertmanager-webhook.yaml` drifts from it.
- CI runs lint → validate (kubeconform + promtool) → security scan (gitleaks +
  kubesec) → deploy → smoke test. Keep manifests passing kubeconform/promtool.

## Secrets

Never log, echo, print, or commit Vaultwarden secrets, kubeconfigs, GitLab tokens,
or `.env` values. Remote URLs may carry embedded GitLab tokens — never paste them
into output or commits.

Before any public GitHub release, verify the repo is clean across history, all
branches, commit messages, and the working tree. These paths/patterns must stay
ignored and untracked; only `.example` templates are allowed in git:

- `gitlab`, `gitlab.pub`, `*.pem`, `id_rsa*`, `id_ed25519*`, `*.key`
- `scripts/alertmanager.yaml`, `**/init.json`, `*token*.txt`, `.secrets`
- `kubernetes/deployments/grafana-gitlab-secret.yaml`
- `kubernetes/deployments/alertmanager-config.yaml`

Before making the repo public, confirm `git ls-files` returns no entries for the
paths above and scan all refs for real-token patterns such as GitLab PATs, Slack
webhooks/tokens, kubeadm bootstrap tokens, private key blocks, AWS keys, and
Google API keys. If any branch tip tracks those files, remove them from that
branch before publishing.

## Code style

- No emojis in code, comments, or commit messages unless asked.
- Default to no comments; only explain non-obvious *why*.
- Edit existing files over creating new ones.
